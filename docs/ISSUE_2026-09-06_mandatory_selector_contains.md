# A required schema-path selector becomes a constraint no ADA record can satisfy

**2026-09-06 · internal · `tools/schema_path_emitter.py` + the schema-path sidecars**

When a schema path carries a selector predicate and the field is required on that side, the
emitter makes the selector's literal **compulsory**. There are **131** such constraints across
`_sources`. The literals are ours, and **none of them occurs anywhere in the 2,621-record ADA
corpus** — so wherever the constrained array is present in a record, that record cannot validate.

Nothing has been changed. This describes the mechanism, the measurement, and the options.

**Read §2 if you read nothing else** — it is the chain from a TAPP row to an unsatisfiable schema.

---

## 1. Correcting an earlier misattribution

This was first written up as an upstream query to the TAPP library and has been withdrawn
(`tapp` @ `2725332`). That framing was wrong. The delivered `Module_Core.csv` says only this about
`Analyst`:

| Metadata Item | Description | C | D | Data Type | Keyed By |
|---|---|---|---|---|---|
| Analyst | Name(s) of the analyst(s)… | N/A | Basic | Text (free) | (none) |

No `schema:contributor`, no `roleName`, and the string `analyst` does not appear. The library says
*required at analysis level, free text*. Everything else is ours.

---

## 2. The chain

**Step 1 — the library states requiredness.** `Analyst` is `C=N/A, D=Basic`.

**Step 2 — we choose a placement.** `docs/modules/Module_Core.schemapaths.csv:14`, `Source=authored`:

```
$Dataset.schema:contributor[schema:roleName='analyst'].schema:name
```

The selector `[schema:roleName='analyst']` and the token inside it were written here. The library
never mentions either.

**Step 3 — the emitter makes the selector compulsory.** `tools/schema_path_emitter.py:461-467`:

```python
elif (skey, val) in node.required:
    key_c = {"const": val}
    allof.append({"contains": {"properties": {skey: key_c}, "required": [skey]}})
```

Its own comment: *"a required object branch must be CONTAINED (selector key = the token/name)"*.

**Step 4 — the generated module carries both halves.**
`_sources/BaseSchema/modules/core/schema.yaml:393` (generated by `build_module_bb.py`):

```yaml
schema:contributor:
  items:
    allOf: [{if: {properties: {schema:roleName: {const: analyst}}, ...}, then: {...}}]   # (a)
  allOf: [{contains: {properties: {schema:roleName: {const: analyst}}, required: [...]}}] # (b)
```

**(a) is right** — it constrains an entry that is present and is silent about the rest.
**(b) is the problem** — it requires such an entry to exist.

### Which bite now

`contains` applies only when the property is present:

| array | records present | effect |
|---|---|---|
| `schema:contributor` | **578 (22%)** | **fails now** |
| `schema:variableMeasured` | **378 (14%)** | **fails now** |
| `schema:step` | 0 | latent |
| `dqv:hasQualityMeasurement` | 0 | latent |

The latent pair is the more awkward: they begin failing precisely when ADA starts recording process
steps and quality measurements.

## 5. Why it stayed invisible

Found while validating five draft TAPPs against their own records. VNMIR, QRIS and XRD came back
clean — but only because **none of their 52 records carries `schema:contributor` at all**, so the
constraint never fired. RAMAN and XANES do carry it: 4 of 4 and 46 of 241 fail.

More broadly, the `geochemProfile` `profile/` schemas have effectively never been run against the
corpus. A sample of `adaEMPA` and `adaTEM` records fails them **40/40 and 40/40**, on
`schema:variableMeasured` and `schema:additionalType`. These constraints do not look wrong; they
are simply untested against data.

---

## 6. Options

1. **Stop emitting the mandatory half.** Keep the `if/then`, drop the sibling `contains`.
   Requiredness would need to be expressed where it can be satisfied — on the property, not on a
   selector literal. Smallest change, and it makes the schemas describe what the data can actually
   look like.
2. **Keep it and align the ADA vocabulary.** Emit `schema:roleName: analyst`, and the named
   `variableMeasured` and `schema:step` entries. This is a change to the ADA writers and to 2,621
   existing records.
3. **Keep it and treat these profiles as aspirational.** Then they should not be what the forms
   application validates against.

The judgement to make first is what a required selector *means*. `$Dataset.schema:contributor
[schema:roleName='analyst'].schema:name` can be read as "the analyst's name goes here" or as "an
analyst contributor must exist". The emitter takes the second reading for every required branch.
For `dqv:hasQualityMeasurement`, pinning `dqv:isMeasurementOf` is a defensible way to say "this
specific quality measure must be reported" — so a blanket change may be wrong for that key even if
it is right for `schema:contributor`.

# `registry/` — shared catalogues

Six generated catalogues shared across all 16 techniques. Each subdirectory has its own README; this
is what they have in common.

| directory | holds | defs |
|---|---|---|
| `analyteColumns/` | column definitions for the analyte keyed table | 212 |
| `channelColumns/` | column definitions for the channel keyed table | 43 |
| `reportedPropertyColumns/` | column definitions for the reported-property keyed table | 1 |
| `parameterTemplates/` | method-level parameter templates (what the procedure specifies) | 320 |
| `parameterValues/` | per-dataset parameter values (what the analysis used) | 749 |
| `vocab/` | SKOS code lists | 256 files |

## They are catalogues, not dependencies

The `$defs` here are **inlined into each technique's generated schema, not `$ref`d** — nothing in
`_sources/` points a `$ref` at a registry `schema.yaml`. Each is declared `isTypeLibrary: true`: a
shared catalogue you can read, diff and publish, while the copy a validator enforces lives in the
technique that uses it.

Keys are namespaced by TAPP prefix (`empa_acceleratingVoltage`) because a bare name collides across
techniques — `detectionLimit` is generated by seven. The `@id` const inside a def carries the same
identity, so a def is unambiguous however it is keyed.

## Two generators write here

| route | tools | writes |
|---|---|---|
| path-driven | `schema_path_emitter.py` via `build_pathdriven.py` | the three keyed-table registries |
| legacy matrix | `build_tapp.py` / `_tapp_lib.py` | `parameterTemplates`, `parameterValues` |

They read different sources — the sidecars versus the richer annotated workbooks — so they can
disagree about the same `@id`. `python tools/registry_ownership.py` reports, per registry, which
defs the two routes agree on, which differ, and which only one route produces.

## Do not hand-edit

Everything here is generated. Fix the source — a `docs/*.schemapaths.csv` sidecar, a table in the
`tapp/` submodule, or the generator — and re-run. A hand edit is overwritten by the next
regeneration, silently.

```bash
python tools/regenerate_schema_json.py     # *Schema.json from schema.yaml
python tools/resolve_schema.py --all       # resolvedSchema.json everywhere
```

One standing gotcha: **`parameterValues` and `parameterTemplates` reformat wholesale on any
regeneration.** After regenerating a single technique, `git checkout` those two files if you only
meant to touch that technique, or the diff carries unrelated reflow.
